# 0.12.2 验证记录

2026-10-19，Windows Chrome默认图形后端、NVIDIA RTX3050 Laptop GPU，1440×1050，均衡画质。未在用户安卓手机上测量帧率。

## 实现与根因

- 太阳与月亮随时刻沿天空升落；月面纹理、光晕、缓慢移动的合批云层。雨雪隐藏日月并加厚深色云，降水粒子的高度跟随山地海拔。
- 铁塔广场原范围x=125..295、z=31.5..198.5，与z=36.8东行道路共面。现在广场避开道路，所有道路交叉口以区域差集构成无重叠铺装，外侧步道避开行车面。
- 348名额外游客、登山者和外围居民；其中136名在山林及登山口。游客覆盖广场、售票区、甬道、两翼展厅和高处观景台，登山者沿共享路线双向行走并停留，脚底高度采样渲染地形。外围运行138辆汽车、面包车、三轮和电动车，另有原村内车流、停放车辆和旅游大巴。
- 车辆按不超过8cm的移动子步测试朝向车身范围。撞到行人后有有限冲量、重力、倒地、起身和恢复过程；倒地期间移除站立碰撞，防止车辆卡住。先检验实体墙，避免隔墙击中；低速碰触不抛人。
- 人车查询改为附近空间网格；远车按低频时间推进。新增人群远处仅一个简化实例批，附近固定16个精细名额，复用模型与材质，而不是每次名单改变整批重建。动态配色随身份更新，未变化的颜色缓冲不上传。
- 自动分辨率曾让Scene订阅并重建整个场景组件树；现由渲染器单独更新，重型世界组件记忆化。首次场景编译、快速区域切换仍会有初始化成本。
- 回归发现雪山出生点位于公路中心，新增车流会挡住起步，现移至路边。铁塔与博物馆的到达点避开候车棚。
- Three r180的compileAsync轮询会在平面图/方案切换释放材质后读取空currentProgram，造成isReady异常。现预热可取消，以原生KHR编译完成状态轮询，并跳过已删除程序。

## 实测与限制

最终景区人群7秒采样：468帧，P95 23.2ms，最大30.1ms，超过50ms为0。12秒直行驾驶358.15米：P95 20.3ms，最大31.7ms，慢帧0，车辆隐藏0帧。10秒持续右转：P95 18.9ms，最大29.9ms，慢帧0，相邻镜头最大转角约2.84度。原始摘要见本目录0.12.2-world-life.json与0.12.2-driving.json。

调整清晰度与人物细节复用修正之前，同类景区采样曾出现约752ms峰值；修正后的这段采样没有复现。场景切换、首次GPU准备、后台窗口状态、不同手机、长时间运行及更多区域仍可能产生卡顿，不据短样本宣称全图流畅。

景观为游戏化地形，交互碰撞不等于完整布娃娃或车辆损毁系统。人车临时位置在重启后复原，方案、门票、探索和聊天记录仍保存在本机。
