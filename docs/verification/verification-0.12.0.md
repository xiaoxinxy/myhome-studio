# 0.12.0 验证记录

2026-10-19，Windows 本机 Chrome。安卓包由原签名构建，未在用户安卓手机上执行帧率实测。

## 检查结果

- npm test：10 个文件、71 项逻辑测试通过。覆盖原户型门洞、驾驶方向与限速、车辆高度碰撞、大巴镜头避让、坐躺、跳跃攀爬、地形支撑、长距离遮挡、公共设施和大巴。
- TypeScript、Vite 生产构建、APK ZIP 路径与对齐、离线资源引用、v2/v3 签名校验通过。
- 最终 APK 的 tests/native.spec.ts 在默认图形后端下通过，用时约38秒，保持原150秒总时限；断网加载真实包资源、照片、PNG原生导出桥、昼夜雨天、平面图、返回、摇杆、窄窗口转向开关、摸猫和方案不变均通过。
- tests/performance-fixes.spec.ts：拖动/悬停切换、8个方向的人物实例颜色审计、四个自然景观抵达、火口观察点、390×844按钮可见、对齐且不重叠通过。颜色审计未发现错色。
- tests/expedition.spec.ts：五地标打卡、地图、路人反应、夺车、高速驾驶、刹车、下车和手机昼夜天气通过，最终相关驾驶修正后约1.3分钟。
- tests/south-yard.spec.ts：南向门可通行，鸡鹅镜头背后提交数为0，转向南院后重新可见，喂食、昼夜雨天、路人和动物通过。
- tests/tourism.spec.ts 与 tests/studio.spec.ts 分批通过，覆盖活动、离线对话、跳跃攀爬、大巴与景区参观、装修修改及PNG/GLB/CSV/JSON导出。

最后一轮以5180提供生产预览，使用独立5182开发服务做源代码交互回归，避免重载用户页面。测试后已关闭5182和测试浏览器。

两次强制SwiftShader的最终离线长流程分别在“选房间”和“画质”操作时耗尽150秒总时限；没有将超时记为通过，也没有延长总时限。改用默认图形后端后同一断言流程通过。较早版本阶段的软件后端离线回归也曾通过，不能据此保证所有低端设备表现。

## 性能采样

采样脚本为 scripts/check-walking-performance.mjs。960×720、均衡、DPR0.8、先预热30帧，再行走采样80帧；前台预览暂切2D，未同时运行其他测试。实际后端：ANGLE / NVIDIA GeForce RTX3050 Laptop / Direct3D11。

|路线|平均帧时间|P95|最大采样帧|绘制调用|
|---|---:|---:|---:|---:|
|自家前院行走|11.25ms|17.10ms|21.60ms|229–236|
|外围道路行走|8.10ms|14.20ms|16.70ms|10–11|

原始数据及渲染器信息在[0.12.0-performance.json](0.12.0-performance.json)。这是本机两段短路线的开发服务采样，不是手机帧率或全地图最差情况。生产预览页面曾观察到约94FPS；同时运行强制软件渲染测试会明显拖慢前台，故测试结束后再体验。

主要减负包括：长射线查询避开海量空网格；家具远距离提前裁剪；小地图底图复用；普通画质使用轻量漫反射光照；远处行走人物降细节；鸡鹅按视野压缩实例；初始化材质预热与极低帧率降档。轻量光照会减少高光与法线细节，精细模式保留原PBR效果。[Three.js材质说明](https://threejs.org/docs/pages/MeshLambertMaterial.html)，[Chromium图形后端参数](https://chromium.googlesource.com/chromium/src/+/main/ui/gl/gl_switches.cc)。
