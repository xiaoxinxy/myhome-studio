# 0.12.1 验证记录

2026-10-19，Windows本机Chrome默认图形后端；没有强制SwiftShader。安卓包原签名构建。未在用户安卓手机上测量帧率。

## 根因与修正

- 全域地图已扩展到x=-1550..2550、z=0..3200，旧行走/驾驶边界却停留在x=-850..1600、z<1800；火山与雪山入口因此不可达。现统一使用outerBounds。
- 公交候车站由x=11迁至x=132的村口公共区域，仍在公交路线和路网中，不再处于自家门轴线上。
- 步行每帧仅使用最多50ms、驾驶最多80ms的旧处理会在慢帧后丢掉经过时间；现在在最多160ms的窗口内按不超过1/60秒的子步推进。超长停顿仍限幅，防止回到前台后飞移。
- 镜头位置平滑而注视点直接跳到新坐标，会在转向和地面高差处产生视觉抽动。现成对平滑，第一人称平移直接跟随，地面高度变化平滑；镜头不再受小型行人碰撞拉扯，并避开山体。
- 自家车辆按原停车位置裁剪，且被整个村庄区域的远距离裁剪隐藏。现按运行时位置判断，独立于静态村庄裁剪；车辆仍位于home-model中，GLB导出保留。

## 帧时间与限制

旧版两段各15秒的本机连续行走采样没有复现超过50ms的长帧，因此没有声称已经量化消除了用户遇到的所有顿挫。此次修正针对可直接核实的时间丢失、镜头不同步和车辆裁剪问题。

最新12秒驾驶采样：1440×1050、均衡、DPR0.8；平均9.65ms，P95 16.30ms，最大24.30ms，超过50ms慢帧0次，车辆被隐藏0帧。见[原始摘要](0.12.1-driving.json)。另补10秒持续加速右转采样，P95 16.20ms，最大26.20ms，慢帧0次，镜头相邻帧最大转角约1.53度。没有逐一覆盖盘山驾驶，不代表全图、手机或长时间游戏表现。

FPS是一个窗口的平均值，不能单独排除顿挫。新版显示慢帧次数，提示给出P95与最大耗时；后台不参与画质降档。山体的近/远细节切换和路面材质初次准备仍可能带来局部峰值，后续应以真实手机记录继续优化。

三座山为压缩的游戏地形。火山、雪山盘山路线绕山超过两圈，富士山采用折返路线；路标显示路程和海拔，山腰雾带与峰顶远眺随昼夜天气显示。护栏为视觉导向，尚无完整车辆悬挂或翻车模拟。
